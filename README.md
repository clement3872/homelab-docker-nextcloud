# Nextcloud (Raspberry Pi, SSO via Authentik)

> Nextcloud deployed on the Raspberry Pi, accessible from the internet via the
> E2E WireGuard+Caddy proxy. SSO via Authentik using the official `user_oidc`
> app. All persistent data lives on the SSD under the compose directory.

## Architecture

```
Browser → VPS nginx (stream/SNI) → WireGuard → RPi Caddy (TLS termination) → Nextcloud (localhost)
                                                                    └→ Authentik (localhost, OIDC)
```

- TLS terminates on **Caddy** (RPi), not on the VPS — VPS sees only encrypted bytes
- Nextcloud binds to `127.0.0.1` only — only Caddy can reach it
- Postgres + Redis are isolated on the `internal` network (no exposed ports)
- User data is split from the app install so it can be relocated to a dedicated
  drive later without touching the Nextcloud code

---

## Prerequisites

- Authentik already running and reachable at `https://auth.yourdomain.com`
- RPi with SSD mounted at `/mnt/sda1/server/`
- Docker + Docker Compose installed
- WireGuard tunnel to VPS active
- DNS A record for `cloud.yourdomain.com` → VPS public IP, Cloudflare proxy **OFF** (gray cloud)
- VPS nginx `stream` map updated (see below)

## Directory structure

```
/mnt/sda1/server/production/nextcloud/
├── docker-compose.yml
├── .env                    ← generated by script, never commit
├── .env.example            ← template, safe to commit
├── generate-secrets.sh
├── data/
│   ├── postgresql/
│   └── redis/
├── html/                   ← Nextcloud app install (apps, config, themes)
└── userdata/               ← user files — the bulk
```

Create the data directories before first boot:

```bash
mkdir -p data/postgresql data/redis html userdata
```

## Authentik — create the OIDC provider

In the Authentik admin UI (`https://auth.yourdomain.com`):

**1. Create provider** — *Applications → Providers → Create → OAuth2/OpenID Provider*

| Field                   | Value                                                         |
|-------------------------|---------------------------------------------------------------|
| Name                    | `Nextcloud`                                                   |
| Authorization flow      | `default-provider-authorization-implicit-consent`             |
| Client type             | `Confidential`                                                |
| Client ID               | *(auto — save it)*                                            |
| Client Secret           | *(auto — save it)*                                            |
| Redirect URIs           | `https://cloud.yourdomain.com/apps/user_oidc/code`            |
| Signing Key             | `authentik Self-signed Certificate`                           |
| Scopes                  | `email`, `openid`, `profile`                                  |
| Subject mode            | `Based on the User's username`                                |

**2. Create application** — *Applications → Applications → Create*

| Field                   | Value                                  |
|-------------------------|----------------------------------------|
| Name                    | `Nextcloud`                            |
| Slug                    | `nextcloud`                            |
| Provider                | `Nextcloud` (the one just created)     |
| Launch URL              | `https://cloud.yourdomain.com`         |

**3. Note the discovery URL** — you'll need it for Nextcloud:

```
https://auth.yourdomain.com/application/o/nextcloud/.well-known/openid-configuration
```

## VPS — `/etc/nginx/nginx.conf`

Add **one line** to the existing `stream` map block:

```nginx
map $ssl_preread_server_name $backend_https {
    ...existing entries (including auth.yourdomain.com)...
    cloud.yourdomain.com    10.0.0.3:443;   # RPi WireGuard IP
}
```

```bash
nginx -t && systemctl reload nginx
```

## RPi — `/etc/caddy/Caddyfile`

```caddy
cloud.yourdomain.com {
    reverse_proxy localhost:9001

    # Nextcloud WebDAV calendar/contacts redirects
    redir /.well-known/carddav   /remote.php/dav 301
    redir /.well-known/caldav    /remote.php/dav 301

    # Larger bodies for file uploads
    request_body {
        max_size 10GB
    }

    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
    }
}
```

```bash
sudo systemctl reload caddy
journalctl -u caddy -f   # watch for "certificate obtained"
```

## First boot

```bash
# 1. Generate secrets
chmod +x generate-secrets.sh
./generate-secrets.sh

# 2. Edit .env — at minimum set NEXTCLOUD_DOMAIN
vim .env

# 3. Create data directories (if not done yet)
mkdir -p data/postgresql data/redis html userdata

# 4. Start
docker compose up -d

# 5. Watch it install (first boot takes 1-2 min on RPi 5)
docker compose logs -f app
# Wait for: "Initializing finished"

# 6. Confirm all 4 containers healthy
docker compose ps

# 7. Smoke test
curl -I http://localhost:9001
# Expect: 302 or 200
```

Open `https://cloud.yourdomain.com` — you should land on the Nextcloud login
with your admin credentials (from `.env`).

## Nextcloud — configure SSO (user_oidc)

Once Nextcloud is reachable, install and configure the OIDC app:

```bash
# Install the official OIDC app
docker compose exec --user www-data app php occ app:install user_oidc

# Register Authentik as a provider
docker compose exec --user www-data app php occ user_oidc:provider \
  --clientid="<CLIENT_ID_FROM_AUTHENTIK>" \
  --clientsecret="<CLIENT_SECRET_FROM_AUTHENTIK>" \
  --discoveryuri="https://auth.yourdomain.com/application/o/nextcloud/.well-known/openid-configuration" \
  --scope="openid email profile" \
  --mapping-uid="preferred_username" \
  --mapping-display-name="name" \
  --mapping-email="email" \
  --unique-uid=0 \
  Authentik

# Verify
docker compose exec --user www-data app php occ user_oidc:provider
```

> The `occ user_oidc:provider` flags can shift between Nextcloud versions. If
> the above syntax errors, run `docker compose exec --user www-data app php
> occ list user_oidc` to see the current subcommands, or configure via
> *Settings → Administration → OpenID Connect* in the UI.

Now `https://cloud.yourdomain.com/login` should show a **Log in with
Authentik** button. Click it, log in via Authentik, and you'll be bounced back
with a fresh NC user auto-provisioned.

### Optional — hide the local login form

Once OIDC is verified working, you can force SSO-only:

```bash
docker compose exec --user www-data app php occ config:system:set hide_login_form --value=true
```

⚠️ This locks out the local admin account from the UI. Keep the admin
password handy — you can always bypass via `occ` or by temporarily setting
`hide_login_form` back to `false`.

## Upgrading

Nextcloud requires sequential major upgrades — **never skip a major version**.
The image handles the occ upgrade steps automatically on container restart.

```bash
# 1. Backup first (see below)

# 2. Update NEXTCLOUD_TAG in .env (one major step at a time)
#    e.g. 33.0.2-apache → 34.0.0-apache

# 3. Pull & restart
docker compose pull
docker compose up -d

# 4. Watch the upgrade run
docker compose logs -f app
# Wait for: "Update successful"

# 5. Verify
docker compose exec --user www-data app php occ status
```

---

## Backup

Minimal viable backup before any upgrade or risky change:

```bash
# 1. Put NC in maintenance mode
docker compose exec --user www-data app php occ maintenance:mode --on

# 2. Dump DB
docker compose exec db pg_dump -U nextcloud nextcloud | gzip > backup-db-$(date +%F).sql.gz

# 3. Snapshot the install + userdata
tar -czf backup-files-$(date +%F).tar.gz html userdata

# 4. Release maintenance mode
docker compose exec --user www-data app php occ maintenance:mode --off
```

## Troubleshooting

**"Access through untrusted domain"** — `NEXTCLOUD_TRUSTED_DOMAINS` didn't
match. Edit `html/config/config.php` and add your domain to the
`trusted_domains` array, or set the env var and restart.

**OIDC redirect loop** — check that `OVERWRITEPROTOCOL=https` is set; without
it Nextcloud advertises `http://` URLs to Authentik, which then redirects back
to `http://` and the browser upgrades to `https://`, losing session state.

**"Your web server is not set up correctly" warnings** — most of these come
from the reverse proxy. Confirm `TRUSTED_PROXIES=127.0.0.1` is set. The
`.well-known` redirects belong in the Caddyfile (above), not in Nextcloud.

**Slow on RPi 5** — bump `PHP_MEMORY_LIMIT` to `1G`, and consider enabling
preview generation only for the file types you actually use (Settings →
Administration → Theming → Preview providers).

**Permissions after first boot** — the Nextcloud image's entrypoint chowns
`/var/www/html` to `www-data:www-data` (UID 33) on startup. If you see
permission errors, check that `html/` and `userdata/` on the host aren't
root-owned from a previous manual `mkdir` as root — if they are, run:

```bash
sudo chown -R 33:33 html userdata
```
